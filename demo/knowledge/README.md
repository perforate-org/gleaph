# Knowledge Graph Demo

A small technical-knowledge graph that exercises Gleaph's graph-native strengths in one demo:
variable-length path matching, shortest paths, graph-constrained semantic (vector) search, and
citation reach. The Graph Explorer embedded by the demo host renders the `knowledge` graph and
runs the prepared queries.

## Quickstart

All commands run from this directory (`demo/knowledge`) against a local network with the
platform deployed (`gleaph network start`), using `gleaph.toml` for the graph/job defaults.

```bash
# 1. Schema: graph type, property indexes, and the document_embedding vector index.
gleaph migration apply

# 2. Bulk load vertices + edges (durable job; state recorded in .load-state.json).
gleaph load --vertices seeds/vertices.jsonl --edges seeds/edges.jsonl

# 3. Ingest deterministic Document embeddings into the registered vector index.
node scripts/gen-embeddings.mjs   # byte-stable regeneration of seeds/embeddings.jsonl
gleaph embed ingest \
  --vertices seeds/vertices.jsonl \
  --embeddings seeds/embeddings.jsonl \
  --graph knowledge

# 4. Register the prepared queries (including the scenario-3 semantic search).
gleaph prepared apply
gleaph prepared status

# 5. Smoke-test a registered query from the shell.
gleaph prepared run variable-length-reach --param name='"Graph databases"'
```

The job key and state file default to `[load] key` / `[load] state_file`; pass `--key` /
`--state-file` explicitly to override. `embed ingest` resolves the same identity, so it walks the
receipts of the exact job that loaded the current seeds.

## Embedding ingestion path

- `seeds/embeddings.jsonl` carries one `{source_id, values}` row per `Document`, generated by
  `scripts/gen-embeddings.mjs`. The generator is deterministic (sha256-seeded, L2-normalized,
  768 dims) — rerunning it must not diff the checked-in file.
- The bulk-load wire carries no embedding bytes by design (ADR 0064 §6): the vector canister is
  the sole owner of embedding data. `gleaph embed ingest` runs strictly after a Completed load:
  it re-reads the vertices NDJSON for `source_id` order, pages the load job's chunk receipts to
  reconstruct `source_id → encoded vertex id`, and pushes batches through Router's existing
  admin batch API (`ingest_vertex_embeddings`). This is the B案 ingestion path: zero canister
  changes, no durable-wire format changes.
- Dimension count and finiteness stay Router-owned (`validate_embedding_values` against the
  registered spec); the CLI validates structural input rules only.

## Prepared queries

1. **Variable-length reach** (`variable-length-reach.gql`) — Concepts reachable through
   `RELATED_TO` in 1..3 hops; surfaces path quantifiers.
2. **Shortest path** (`shortest-path.gql`) — `MATCH ANY SHORTEST` between two concepts;
   surfaces graph-native shortest path.
3. **Graph-constrained semantic search** (`team-readable-documents.gql`) — `SEARCH` over the
   `document_embedding` vector index for Documents about `$query`, constrained to public
   Documents owned by members of Team "Platform". `$query` is the encoded F32 vector produced
   by the embedding generator.
4. **Citation reach** (`citation-reach.gql`) — Documents reachable through `CITES` up to depth
   N, returning edge identities.

## Demo host

The primary surface is the Graph Explorer embedded in the demo host (`src/`, Vite). It loads
the whole `knowledge` graph through the SDK `GraphLoadSpec`, runs selected prepared queries, and
highlights returned nodes/edges via the query overlay without rebuilding the scene. Frontend
development follows the standard Vite workflow:

```bash
npm install
npm run dev
```
