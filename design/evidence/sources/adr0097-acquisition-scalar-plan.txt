# Prepared Paged-Map Edits for Span Publication

## Objective

**Draft only; no implementation or execution authorization.** Establish the generic ordered-map
boundary required by the selected nonpublishing acquisition/retirement protocol. A batch that cannot
be prepared leaves canonical map bytes unchanged; a ready object excludes intervening map mutation,
publishes once without expected errors/reservation/allocation, or explicitly discards without writes.
Scalar insert/remove use the same rule. This is not full A0, acquisition cancellation or A1.

## Scope

One map-owned prospective edit engine, shared by immediate scalar insert/remove and the proposed
public `Edit` / `PrepareError` / opaque `PreparedEdits` API. Public preparation borrows `&mut self`;
scalar `&self` calls prepare and consume privately within one synchronous method. The same map
cannot be mutated or prepared twice while a public ready object remains live. Exclusive backing
ownership remains required; independently reopened/raw-memory aliases are not a new supported mode.

Ordered intents return one prior value each, preserve missing-remove `None`, and see previous intents'
prospective changes. Support repeated keys, first/minimum changes, splitting, singleton removal,
page reuse, complete drain/reset and insertion after drain. No sorting away caller order. A later
remove cannot rescue an earlier `DirectoryFull`. Encountered corrupt geometry/membership/links and
checked address overflow reject before publication; no whole-map validation on every edit.

Use one private dirty-range image, governed by
[ADR0088's scalar storage contract](../design/adr/0088-tree-csr-mode-for-high-degree-label-buckets.md#scalar-dirty-write-and-scratch-contract):
inline small edits/results, dynamically reserved overflow only when needed. No obligatory page
image, per-scalar vector, whole-store snapshot or general undo/write-log framework. Its publisher is bound to
its owner, has no destination argument, performs no validation, heap allocation, grow, split or
fallible encoding, and has no recoverable result. `discard(self)` releases buffers/borrows only;
no custom cleanup Drop. Growth during preparation may remain, but canonical bytes must not change.
Do not claim global zero allocation from owner counters or zero stable-page growth.

`PrepareError` keeps intent index and exact `Error`, `GrowFailed`, address-overflow or scratch cause.
Scratch needed to represent an earlier intent may preempt an unvisited later error; do not promise
all semantics before all scratch allocation. Reserve checked **allocated page extents**, not merely
the highest dirty byte; reopen requires backing for full minted pages. For a grow, record the intent
establishing the highest required page. Reuse the map's layout constants/encoders; no layout arithmetic moves into LARA.

Keep current scalar signatures and explicit projections: existing `DirectoryFull`/`Corrupt` remain
exact; grow and scratch exhaustion use the scalar `OutOfMemory` surface. Retain only the already
existing `alloc_page` overflow-to-`OutOfMemory` projection at that facade; new preparation reports
`AddressOverflow` separately. Document this distinction rather than using the lossy facade in A0.
All such scalar errors must occur before writes. Do not extend the existing scalar `Error` enum,
add a fallback scalar editor or a second page/directory algorithm. Initialization remains a distinct fresh-region operation.
