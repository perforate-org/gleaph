# Non-destructive allocator admission

## Objective

**Revise mode; prose only, no implementation or execution authorized.** Deliver one useful
existing-owner repair: on valid initial backing, malformed exact-span/pair requests and
zero/already-backed index reservation must not change canonical allocator/index state. It is independently useful without
prepared release batches, native demotion or physical caller wiring.

The [A0 interface checkpoint](../design/evidence/adr0097-demotion-design.md#stage-a-reslicing-and-interfaces)
is the source of truth for proposed types, borrow authority, batch ordering, errors, heap bounds
and cancellation limits. Complete A0 needs a public generic paged-map checked-edit capability and
acquisition provenance/nonfailing cancellation at `lara/edge/span.rs`; release-page reservation
cannot supply either. **This smaller slice does not implement or validate those capabilities.**
Do not replace full-A0 acceptance criteria with these four admission tests.

## Scope

One admission boundary in the existing two stores. Preserve public signatures, returned errors,
wire layouts, allocation policy, 512/1024 thresholds and the fast prefix-restoration probes.
No prepared token, mutation guard, public checked-edit API, allocator batch, heap redesign,
transaction/undo layer, cache or persistent state belongs in this smaller implementation.

Exact-record admission has one private owner:

```rust
fn exact_span_record(&self, span: FreeSpan)
    -> Result<(SpanId, SpanRecord), FreeSpanError>;
```

It resolves the start key and checks active flag, stored start and length before any removal.
Reuse it in `replace_existing_span`, `remove_span_exact` and pair admission; delete superseded
`ensure_span_exact` and remove-then-reinsert compensation. No public visibility expansion.
Pair rejection order remains: left exactness → right exactness → replacement empty/end checks →
existing replacement-neighbor checks → identical input IDs (`MissingSpan { span: right }`) →
unrelated replacement-key collision (`DuplicateStart { start_slot: replacement.start_slot }`).
Ignore only the two proven input keys in the last check. These last two errors already occur in
that order after destructive work; move their discovery before it. Do not reuse cached bin-link
fields across pair removals: removing the first record can change the second record's links.
This does not make valid pair replacement or later map/bin/heap failures atomic.

In `reserve_for_inserts`, return immediately for zero and skip the sentinel write when existing
backing already covers the computed need. Keep positive-request sizing and `GrowFailed` behavior
unchanged; do not represent its current saturating arithmetic as a new checked-capacity proof.
Clarify the existing method's rustdoc: no-growth reservation is nonwriting; directory exhaustion,
corruption and heap allocation are not admitted by it. No executable doc example changes.
