# Prepared physical edge-span publication prerequisite

## Objective

**Draft for review; implementation and validation are not authorized.** Stage A of the
[demotion/deletion proof map](../design/evidence/adr0097-demotion-design.md#staged-implementation-and-tests--all-planned-none-run)
prepares the physical write boundary needed by native conversion. A recoverable rejection must
precede the first canonical row/prefix/root/count write. Successful physical relocation must retain
logical positions, initialized holes, independent runs, root IDs and peer ownership.

This slice does not close GAP001/003, enable live property deletion, or introduce a second placement
algorithm. If later native-conversion slices never happen, its standalone result is a stronger
existing physical publication owner with unchanged public behavior and precise failure semantics.

## Scope

In scope: the existing physical preparation/commit execution flow, its three callers and bypass
path, checked geometry/descriptor/counter serialization, nonpublishing reservations, cleanup
ownership and focused tests. No semantic compaction or tree deletion. Explicitly distinguish old
physical ownership from destination descriptors/images so a later replacement cannot free a target
as if it were a source. Use the existing allocators, not an exclusion map or new store.

A single private prepared-layout value may own the already validated publication inputs and cleanup
obligation. It is not public/persisted/clonable; do not add mode flags, a generic transaction layer,
a new module/dependency or a longer argument list. Delete superseded planning paths rather than
leaving parallel safe/unsafe entry points. Ordinary rewrite and both relocation call sites must
consume the same preparation invariant; a demotion-only alternate commit is not acceptable.

Non-goals: native selection/retirement or assertion removal; matching mutation; GAP002/005/007;
threshold/header/layout changes; logical movement/cursor changes; Graph API or sidecar redesign;
new benchmarks, 16K replay, full suite, persistent benchmark campaign, PocketIC or merging.
The physical owner does not promise IC rollback or generic native panic recovery.

## Steps

1. Record all three commit callers, bypass symmetry, first possible canonical write in each outer
   flow, old owner extents and allocator release ownership. Specify the private preparation value
   and how destination reservation avoids publishing peers. Check typed errors by failure site,
   not outer enum name. Source audit is not runtime proof. Resolve signature/ownership review
   before expanding the 12-argument helper or touching allocator APIs.
2. Add four tests named below against existing execution entry points, not a parallel test-only
   demoter. Use canonical backed fixtures and distinct outside/neighbor bytes. Run the smallest
   baseline only after separate authorization; setup/compile failures are not runtime reds. Do not
   reapply the saved assertion-only deletion diagnostic.
3. Prepare checked positions, byte images, encoded bucket/vertex rows, prospective counters,
   ownership inventory and cleanup reservations before any canonical write. Keep old pinned leaf
   ownership distinct from bucket subspans and replacement images. Acquire disjoint unpublished
   targets without driving an observable peer rewrite; route every current caller through the one
   owner. Publication consumes prepared data without new allocation/source discovery or recoverable
   checks. Preserve the existing one-move slab compaction/cursor/fallback and observer contracts.
4. Prove each rejection releases unpublished targets while preserving canonical source/peers;
   monotonic memory growth is allowed, not free/active overlap. Do not use `let _ =`, a debug
   assertion or `catch_unwind` as cleanup. A post-publication violation aborts native execution;
   it is not recoverable rollback. Run the scoped checks/sensitivity cases under the later agreed
   budget, restore all mutations/probes, review source/complexity and update status only for A.
